# Economy catalog audit

The runtime catalog pins the existing Victoria quest/drop/map generated facts, NPC shop SQL, global
and monster drop SQL, and a Map.wz-derived NPC location index. The bundle hash changes when any
input changes, and a checkpoint cannot be resumed against a different hash.

`npc-locations.json` is generated by `EconomyNpcLocationCatalogExportTest` through Cosmic's real
`DataProvider`; it does not parse or classify WZ nodes independently. Every normal SQL shop NPC has
physical map evidence. Two special/unplaced rows do not:

- `9001002` (Polar bear Poch): the same id appears as a monster in Map.wz, not a placed NPC.
- `9090000` (Mu Mu): no NPC life placement exists in Map.wz.

They are intentionally inaccessible to remote simulation commerce. This is preferable to assigning
a fictional map. `RemoteNpcCommerceService` fails closed whenever source-map evidence is absent.

Accepted quest demand reads remaining item requirements from the live `Quest.wz` objects rather
than the inherited level-25 adaptive subset. Activity map selection uses the generated Victoria
map/spawn catalog, but economic production requires a matching real-session calibration for the
exact agent build, job family, nearby level, and map. Missing calibration is a run-stopping input
error, not an invitation to estimate kills.
